## 0. 产品定位（✅）

**通用型企业外贸展示网站**：为外贸企业提供中英文（可扩展多语种）双语产品展示前台与内容管理后台。

| 项 | 结论 |
|---|---|
| 形态 | **通用型产品**：同一套代码服务不同企业，非一次性定制 |
| 租户模型 | **A 单租户单站**（本期）—— 一套部署服务一家企业，站点设置是全局单例 |
| 前台受众 | 海外采购商 / 访客（英文为主）|
| 后台受众 | 企业内容运营者 |
| 前台渲染 | **A 构建期静态预渲染（SSG）** |
| 部署 | **前后端分离，两台服务器**（A 机站点静态托管 / B 机应用与数据库）|
| 数据库 | SQLite 起步；**预留 PostgreSQL 对接模块**（🔜）|
| 实时能力 | **仅 SSE**，场景唯一：新询盘到达时后台提醒（❌ 不引入 WebSocket）|
| 横切能力 | RBAC · 报表与导出 · 审计日志 |

### 定位推导出的三条"不可协商"

1. **SEO 是核心功能，不是优化项。** 外贸客户流量来自 Google 自然搜索 → 采取 SSG，
   且所有对外内容必须有**可静态生成的独立 URL**。
2. **多语言是 URL 结构问题，不是翻译问题。** 每语种独立路径 + `hreflang` 互指，
   业务数据**逐字段**双语。
3. **时区只影响"显示"。** 存储一律 UTC，展示层转换。

> **单租户是本期选择，但"通用型"意味着未来可能演进到多站点。**
> 因此本期**不引入租户维度**，但业务表的唯一键设计不要假设"全局只有一条"，
> 给演进留余地（详见 `strata-index.md` §4 陷阱 P-09）。

## 4. 部署拓扑（两台服务器）

```
        ┌─────────── A 机（站点前端）───────────┐
访客 ──►│ nginx                                  │
        │  ├─ /            前台 SSG 静态产物      │
        │  ├─ /admin/      后台 SPA 静态产物      │
        │  ├─ ^~ /api/  ── 反代 ──────────────────┼──┐
        │  └─ ^~ /events/ ── 反代（SSE 不缓冲）───┼──┤
        └────────────────────────────────────────┘  │
                                                    ▼
                            ┌─────────── B 机（应用）───────────┐
                            │ node + Fastify（systemd）          │
                            │ SQLite（起步）→ PostgreSQL（预留）  │
                            │ 媒体文件本地磁盘（预留对象存储）    │
                            └───────────────────────────────────┘
```

**决策**：本期采用**同源反代**（A 机把 `/api`、`/events` 反代到 B 机），
不采用真跨域。这样一次性规避 CORS、Cookie `SameSite`、SSE `Origin` 三类问题。

## 6. 决策记录（v1.0 收束）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 产品 | 通用型企业外贸展示网站 |
| 2 | 租户模型 | **单租户单站**（本期）|
| 3 | 前台渲染 | **SSG 构建期预渲染**（否掉 SSR 与纯 SPA）|
| 4 | 实时推送 | **仅 SSE**，场景 = 新询盘后台提醒；**否掉 WebSocket** |
| 5 | 数据规模 | SQLite 起步，**预留 PostgreSQL 对接**（🔜）|
| 6 | 可选模块 | 询盘 RFQ / 产品搜索 / 新闻资讯 / 批量导入导出 / xlsx 导出 / **≥3 语种** / TOTP —— **全部采纳** |
| 7 | 部署 | 两台服务器，同源反代，单仓双部署单元 |

**否掉的选项及理由**（留档，避免日后反复）：

| 否掉的 | 理由 |
|---|---|
| 多租户 SaaS | 本期单租户；"通用型"靠"每企业一套部署"实现，不靠共享实例 |
| SSR（Nuxt）| 已选 SSG；本期不引入常驻渲染进程 |
| 纯 SPA | 外贸站流量靠自然搜索，产品页无法被抓取 |
| WebSocket | 唯一实时场景是单向通知，SSE 足够；WS 会引入跨域 `Upgrade` 放行、连接鉴权、断线重连、多进程状态不共享等一整套分散成本 |
| ISR 运行时 | 内容变更改为触发重建，不引入运行时增量渲染 |
