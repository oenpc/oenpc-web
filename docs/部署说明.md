# OENPC-WEB 部署说明（Linux + nginx + systemd）

> 目标形态：**A 机放静态产物与 nginx，B 机跑 node 应用与数据库。**
> 本轮上线的是**最基础可用**的一组功能：前台展示 + 后台登录 / 产品管理 / 图片上传。
> 尚未实现的部分见文档末尾「本轮没做的」，避免误以为已经齐全。

---

## 0. 前置检查（**先做这一条，否则会白折腾**）

```bash
node -v      # 必须 >= 22.19.0 —— 服务端用了内置 node:sqlite，低版本直接启动失败
pnpm -v      # 需要 pnpm；没有就先 `npm i -g pnpm`
nginx -v
systemctl --version
```

> **为什么死守 22.19**：`engines` 里锁了这个版本，而 `node:sqlite` 是内置模块 ——
> 换用第三方 SQLite 驱动意味着要改数据层、加原生编译依赖，
> 这与"上传即可跑"的目标冲突。**不要在低版本 Node 上试。**

---

## 1. 目录规划

```
/opt/oenpc-web/
├── server/            # B 机：应用代码 + 运行期数据（这个目录要可写）
│   ├── dist/          #   tsc 产物
│   ├── node_modules/  #   生产依赖
│   ├── .env           #   ★ 配置（不入库）
│   └── data/          #   ★ SQLite 库 + 媒体文件（不入库，必须备份）
└── ...

/var/www/oenpc-web/
├── site/              # A 机：前台 SSG 静态产物（web/dist/client）
└── admin/             # A 机：后台 SPA 静态产物（admin/dist）
```

> **`data/` 是最重要的目录**：数据库与上传的图片都在里面。
> 它不随代码发布更新，**升级时千万不要删**。

## 2. 在服务器上构建

本项目**在服务器上构建**（而不是本地打包上传），因为前台是 SSG ——
它的页面是从 API 拉数据**构建期生成**的，所以构建时后端必须在运行。

```bash
git clone <仓库地址> /opt/oenpc-web-src && cd /opt/oenpc-web-src
pnpm install
pnpm typecheck
pnpm test                 # 41+ 项测试；失败就别继续
pnpm build                # shared + server → 产出 dist
```

---

## 3. 建管理员账号（**没有它进不了后台**）

```bash
OENPC_WEB_DB_PATH=/opt/oenpc-web/server/data/oenpc-web.db \
  node scripts/create-admin.mjs admin '<自己设一个强口令>'
```

- 第一个账号自动是**隐式全权**（否则没人能再授权，系统会锁死）
- 口令至少 8 位，且不能与用户名相同
- 改口令：加 `--reset`；改口令会**一并清掉该账号所有有效会话**

> 本项目**不预置默认账号**。`admin/admin123` 那种做法等于给每个忘了改口令的部署
> 留一个公开后门，而"忘了改"是常态。

---

## 4. 配置 `.env`

```bash
mkdir -p /opt/oenpc-web/server
cp .env.example /opt/oenpc-web/server/.env
```

必须改的几项：

| 变量 | 说明 |
|---|---|
| `OENPC_WEB_HOST` | **生产要设成 B 机的内网地址**（如 `10.0.0.2`）。默认 `127.0.0.1` 时 A 机连不上；**不要设 `0.0.0.0` 直接把端口暴露到公网** |
| `OENPC_WEB_DB_PATH` | 绝对路径，如 `/opt/oenpc-web/server/data/oenpc-web.db` |
| `OENPC_WEB_MEDIA_DIR` | 绝对路径，如 `/opt/oenpc-web/server/data/media` |
| `OENPC_WEB_SITE_URL` | **生产必填**，如 `https://trade.example.com`。不填则 sitemap 与 hreflang 会生成指向错误域名的绝对地址**且不报错** |
| `OENPC_WEB_TRUSTED_PROXY` | **填 A 机的内网地址**（如 `10.0.0.1`）。见下方说明 |

### ⚠ `OENPC_WEB_TRUSTED_PROXY` 不配会发生什么

不配时，应用看到的每个请求来源都是 **A 机的 IP**，于是：

- 日志里所有访客是同一个 IP，排查攻击来源完全无用；
- **登录限流退化成"限流全站"** —— 暴力破解触发一次，把所有管理员一起锁在门外。

但也**不要填 `true`**（信任一切）：客户端可以伪造 `X-Forwarded-For` 绕过限流。

## 5. 安装 systemd 单元并启动

```bash
sudo useradd --system --home /opt/oenpc-web --shell /usr/sbin/nologin oenpc-web
sudo mkdir -p /opt/oenpc-web/server
# 把 dist / node_modules / package.json / .env 放到 /opt/oenpc-web/server
sudo chown -R oenpc-web:oenpc-web /opt/oenpc-web

sudo cp deploy/oenpc-web-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now oenpc-web-server
sudo systemctl status oenpc-web-server
```

看日志与自检：

```bash
sudo journalctl -u oenpc-web-server -f
curl -s http://10.0.0.2:3900/api/health | head -c 400
```

`/api/health` 会回报**数据库实际路径与已应用迁移数** —— 这两个信息能回答
"数据写哪去了""迁移跑了没有"，比一句 `{"status":"ok"}` 有用得多。

## 6. 配置 nginx（A 机）

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/oenpc-web.conf
sudo nginx -t && sudo systemctl reload nginx
```

**动手前先读 `deploy/nginx.conf` 里的注释** —— 尤其是这三条：

1. `/api/` 与 `/media/` 必须用 `^~` 且写在 `location /` **之前**。
   否则前台 SPA 回落会把它们吃掉，前端拿到 HTML 而不是 JSON，
   报错是 `Unexpected token '<'`，看起来像前端 bug。
2. `client_max_body_size 12m` 必须放开。nginx 默认只有 1m，**上传会在 nginx 就被 413 拦掉，
   根本到不了应用**（硬约束 `upload-limits-both-sides`）。
3. `/admin/` 的路径必须与 `apps/admin/vite.config.ts` 的 `base: '/admin/'` 一致。
   不一致时后台资源请求落到前台站点，同样是 `Unexpected token '<'`。

## 7. 构建前台与后台，放到 A 机

**顺序很重要**：先让后端跑起来并录好内容，再构建前台 ——
前台是 SSG，**构建期从 API 拉数据**，没有数据就产出空站点。

```bash
cd /opt/oenpc-web-src

# 后台 SPA（不依赖数据，随时可构建）
pnpm --filter @oenpc-web/admin build

# 前台 SSG（★ 依赖运行中的 API 与里面的内容）
OENPC_WEB_SITE_URL=https://trade.example.com \
OENPC_WEB_API_BASE=http://10.0.0.2:3900 \
  pnpm build:web

# 部署到 A 机
sudo rsync -a --delete apps/web/dist/client/ /var/www/oenpc-web/site/
sudo rsync -a --delete apps/admin/dist/       /var/www/oenpc-web/admin/
```

> **改了产品内容之后，前台不会自动更新** —— 它是静态页面，必须重跑 `build:web`。
> 后台编辑页底部有这条提示。这不是"保存失败"（对应索引里的陷阱 P-08）。

## 8. 首次验证顺序（照着走一遍）

1. `curl https://<域名>/api/health` → 200，`appliedMigrations` ≥ 2
2. 打开 `https://<域名>/admin/` → 能登录
3. 后台「产品 → 新建产品」→ 填 **zh 与 en 两个语种** → 上传一张图 → 勾「上架」→ 保存
4. 重跑第 7 步的 `build:web` 与 rsync
5. 打开 `https://<域名>/en/products/<你填的 slug>` → 应看到产品与图片
6. `https://<域名>/sitemap.xml` → 应包含刚建的产品 URL
7. 查看页面源码，`<head>` 里应有 `canonical` 与多条 `hreflang`

## 9. 备份（**别跳过**）

```bash
#!/bin/bash
# /etc/cron.daily/oenpc-web-backup
set -e
DEST=/var/backups/oenpc-web/$(date +%F)
mkdir -p "$DEST"
# ★ 用 sqlite3 的 .backup 而不是直接 cp —— 直接复制正在写的库会得到损坏的文件
sqlite3 /opt/oenpc-web/server/data/oenpc-web.db ".backup '$DEST/oenpc-web.db'"
tar czf "$DEST/media.tar.gz" -C /opt/oenpc-web/server/data media
find /var/backups/oenpc-web -mtime +30 -delete
```

数据库与媒体文件**必须一起备份**：库里存的是媒体 id，图片文件在磁盘上，
只恢复其中一个会得到一堆破图。

## 10. 升级步骤

```bash
cd /opt/oenpc-web-src
git pull
pnpm install
pnpm test && pnpm build
sudo systemctl stop oenpc-web-server
sudo rsync -a --delete --exclude data --exclude .env dist/ node_modules/ package.json \
  /opt/oenpc-web/server/
sudo systemctl start oenpc-web-server     # 启动时自动跑迁移
```

> `--exclude data --exclude .env` 是**必须的**，漏了会把数据库和配置一起覆盖掉。

## 本轮没做的（**别以为已经有**）

按功能清单对一下，以下都还没实现：

| 缺口 | 影响 |
|---|---|
| **图片压缩 / 缩略图** | 原图直出，上限 10MB。前台首屏可能很重（外贸站对首屏敏感） |
| **图片宽高未解析** | `width`/`height` 恒为 null，前台必须用 CSS 固定容器比例，否则加载时布局跳动（拉低搜索排名） |
| **规格参数编辑界面** | 数据模型与接口支持，但后台没有编辑 UI（保存时会原样保留，不会被清掉） |
| **分类管理** | 表结构在，没有界面，产品一律 `categoryId = null` |
| **询盘（RFQ）** | 未实现。当前访客除了点购买链接跳走，没有第二条转化路径 |
| **首页区块 / 关于我们 / 新闻** | 未实现，前台首页是固定内容 |
| **用户与角色管理界面** | 只能靠 `create-admin.mjs` 建账号、直接改库分配权限 |
| **报表与导出、审计查询界面** | 审计**已在写**（登录、产品增删改、媒体上传删除），但没有查询界面 |
| **TOTP 两级验证** | 未实现 |
| **内容变更自动重建** | 目前必须手动重跑 `build:web` |
| `.vue` 的静态类型检查 | 只做了模块形状声明，模板与 script 里的类型错误发现不了（需要 `vue-tsc`） |

功能清单里标 ✅ 的项在本轮**并不全部可用** —— 那些 ✅ 表示"需求已确认"，
不代表"已实现"。以本表为准。
